# Portable scanner core

Public headers under `include/` require only C++20. OpenCV matrices, allocation and SIMD kernels stay under `src/`; Android JNI wrappers retain registration and platform handle extraction. `Tensor.hpp` owns tensor metadata validation, separable integer RGB resampling/normalization and nine-float prediction interpretation. Field and page-edge kernel bodies are separated mechanically without changing arithmetic or threading. Field arithmetic and normalization retain `-ffp-contract=off` on Android; MSVC core uses `/fp:strict`.

Pixel layouts describe encoded storage, positive byte row/pixel strides, an encoded-coordinate crop, and TIFF/EXIF orientation 1–8. The boundary validates the entire encoded span, including the last pixel, without requiring padding after the last row. It does not apply crop/orientation or model resizing. Geometry values are immutable; public quads remain normalized upright TL/TR/BR/BL.

`Geometry.hpp` owns encoded/upright transforms, normalized/image coordinates, region mapping, photo inference crops, crop editing, render validation/sizing and clipped output polygons. Coordinates use image edges (`0..width`, `0..height`); the explicit pixel-center orientation matrix uses `width-1`/`height-1` for bitmap adapters. Centered square framing is a region transform, including fractional edges for odd dimensions, independent of tensor resizing. Android's CameraX viewport still owns the negotiated framing crop; bitmap allocation and gestures remain Android-owned. The shared geometric stage owns its OpenCV warp resources. Model-output interpretation and photo crop selection share prediction validity without applying the editor's minimum area.

`RenderGeometry.hpp` owns the pre-filter geometric stage: selection of the target canvas, Point2f homography/inversion, page-edge detection/fitting, straight or strip-based curved resampling, the straight coverage mask and normalized valid-content polygon. It borrows a full upright RGBA8 `PixelLease` (packed pixels, optional row padding, at most 4096 pixels per side) and returns independent `OwnedPixels` plus value metadata. No borrowed address survives return. Pixel-center remapping preserves fixed submitted corners; outside corners disable all bending, and unsupported individual sides stay straight. Detection and fitting preserve the 800 px canvas, 6% band, 31 stations, existing thresholds/iteration order and float32 remap offsets. `NativeRenderGeometry` retains source Mat storage for the call and copies the immutable result into Android's mutable filter input. Decoding, encoding, thumbnail registration and file publication remain platform-owned, inside the existing FastCores render scope.

`DocumentFilters.hpp` owns the post-warp filtered-image stage: optional shadow removal first, then none/enhance/grayscale/blackWhite. It borrows full upright RGBA8 pixels through a lease (padded rows, at most 4096 per side), never mutates them, and publishes independent RGB8 or gray8 pixels. Shadow-only diagnostics return RGBA8 with alpha preserved. Private OpenCV resources use RAII; the same existing field kernels retain arithmetic and worker behavior. Paper estimation, channel gains, tile ink measurement/fill and tone curves live in `src/DocumentFilters.cpp`. Android's adapter copies output to a caller-owned Mat and converts RGB to the existing BGR encoding contract. Renders request shadows and filtering together; editor bitmap previews request filtering only at their existing reduced size. Their existing FastCores scopes remain in place. These owning conversions add copies; no performance claim is made for the migration.

`GrayscalePng.hpp` owns four-bit grayscale quantization, high/low-nibble packing, adaptive PNG predictors, level-4 zlib compression, CRCs and chunk serialization. It accepts full upright gray8 pixel leases with padded rows or a synchronous reader returning one owned row lease at a time. Output sinks synchronously consume complete borrowed spans or throw; any row/sink exception unwinds compression immediately. Neither pixels nor callbacks escape, and the writer never flushes/closes a stream or publishes a file. The raw compressed variant emits the same concatenated IDAT payload for PDF Predictor 15 / four-bit samples. Android retains Mat/bitmap row reads and temporary-file ownership, copying one reused Java row into native owned storage before each core lease. PNG passthrough probing now lives with the shared PDF writer; Kotlin retains only a file-copy/value adapter. Compression needs `ZLIB::ZLIB` from `find_package(ZLIB REQUIRED)` (Android uses NDK system libz); host builds must supply a compatible zlib development package through standard CMake search paths or `ZLIB_INCLUDE_DIR` / `ZLIB_LIBRARY`.

`PdfWriter.hpp` owns PDF option validation, page/aspect/DPI sizing, EXIF placement matrices, eligible JPEG/four-bit PNG structural probing, unchanged payload selection, image dictionaries (including gray masks), object numbering, clipped page content, stream lengths, xref and trailer serialization. `pdf::ImageAdapter` supplies synchronous random reads, fallback dimensions, EXIF and platform re-encoding. The core consumes and releases one page before opening the next; source/encoded handles and callbacks never escape the write. JPEG-quality presence forces JPEG re-encoding, including explicit zero, while eligible unscaled gray PNGs retain their compressed data regardless of that override. RectF-compatible rounding preserves the existing placement contract. A sink or source error stops immediately; only Android opens/syncs/closes temporary files and atomically replaces the destination. The Android codec still samples, scales and flattens on white, using the shared gray encoder for four-bit resizes. JNI retains one encoded Java byte array at a time and copies bounded chunks through local arrays; this is ownership adaptation, not a performance claim. Passthrough structurally bounds PNG/JPEG reads but preserves the previous PNG reader's no-CRC-check behavior. Classic xref offsets are limited to ten decimal digits; an oversized result fails before platform publication.

`Motion.hpp` owns optical-flow feature masks, selection and forward/backward tracking, regional coverage/loss and worst-region speed, deterministic similarity-seeded homography fitting, rotation homographies, gyro integration/peak rate and exposure blur. `motion::FlowEstimator` is one camera's analysis-serial state; it synchronously borrows an RGBA8 lease (padded rows/pixels, encoded crop, camera rotations 0/90/180/270), computes the existing integer luma and area reduction to 224 px, and retains only its own gray reference. Every delivered update replaces the reference, including unknown estimates; reset/geometry changes/nonincreasing timestamps/gaps start a new chain. Exceptions break the reference. Central rectangles and quad polygons retain Android Java OpenCV's integer coordinate truncation. No source owner/address survives return. Status, optional speed, confidence, valid/lost tracks and optional transform are value evidence; unknown remains unknown. `FlowHistory` owns the contiguous interval chain, bounded to 32 steps / 500 ms, and rejects gaps, backwards requests and partial intervals. Android lazily creates both native resources on analysis and closes them after queued work drains.

Gyro samples cross as chronological value snapshots from the platform's synchronized sensor history. Acquisition, sensor timestamps, camera metadata and clock conversion remain platform-owned. `ClockCorrelation` is optional and explicitly maps camera time to gyro time; absent correlation returns no gyro answer. Android supplies zero offset only for its documented shared sensor clock, and camera callers remain disabled unless Camera2 reports REALTIME timestamps. Missing gyro/flow evidence never becomes zero motion. C++ owns no sensor thread or platform resource. Only optional transform-fit diagnostic duration reads `steady_clock`; policy and sensor decisions use supplied timestamps. Host OpenCV configuration now requires `video` in addition to `core` and `imgproc`; Android continues using its existing single runtime.

`TensorPreprocessor` is a serial-owner workspace with selection-driven target dimensions (including rectangular inputs). It applies the encoded crop and EXIF orientation at pixel centers, then resizes that entire upright region independently of framing. Output is borrowed writable float32 NHWC RGB storage. Neither source nor output addresses survive `prepare`. The Android adapter owns bitmap locks and direct-plane buffer references; the interpreter consumes the completed tensor on its existing worker. Malformed/nonfinite predictions throw; finite invalid geometry returns no candidate. Score remains ranking evidence with no acceptance threshold.

Adapters supply a `PixelLease` whose owner token keeps both storage and any platform lock alive. The token must cover the supplied span and prevent mutation/reallocation for the lease lifetime. Algorithms synchronously borrow `const PixelLease&` and must not retain its view or pixel addresses. Copies extend the lease; the final token destruction releases the platform resource. Thread-affine tokens stay on their platform serial owner. `OwnedPixels` publishes immutable storage and can release its own handle while a lease remains alive. No JNI, Nitro, Android, UIKit or OpenCV type enters the public headers.

Policy timing for later migrations: callers supply signed 64-bit monotonic nanoseconds from one documented clock domain per camera. For Android policy migration, use `SystemClock.uptimeMillis() * 1_000_000` (monotonic uptime excluding deep sleep), preserving current capture/focus deadline semantics. Sensor elapsed-realtime timestamps must be mapped explicitly before policy comparison; never compare clock domains directly. iOS adapters must establish their domain explicitly. Policies read no clock and own no thread or timer. A waiting decision returns its absolute deadline in the same domain (as `CaptureDecision.Wait` does today). The adapter owns wakeups and cancels them by generation. Policies without deadlines need neither a timer nor a generic policy interface.

Android must provide the existing imported `OpenCV::opencv_java4` target. The core never discovers or bundles another Android OpenCV runtime, so FastCores continues to pin that runtime's workers. Standalone host builds use an explicitly selected OpenCV configuration; this is a separate process from Android.

Live guide acceptance/expiry and tracked retention, adaptive inference wake decisions, score rejection and the low-score movement wake threshold are value-only policies in `LiveGuide.hpp` / `LiveGuide.cpp`. Their Android adapter shares one analysis-executor native owner; scheduling, generation invalidation and publication remain platform-owned. `live_guide_contracts` covers deterministic replay and the preserved thresholds.
