# Portable scanner core

Public headers under `include/` require only C++20. OpenCV matrices, allocation and SIMD kernels stay under `src/`; Android JNI wrappers retain registration and platform handle extraction. Tensor preprocessing stays in its current wrapper until Task 06 migrates its algorithm and assertions. Field and page-edge kernel bodies are separated mechanically without changing arithmetic or threading. Field arithmetic and normalization retain `-ffp-contract=off` on Android; MSVC core uses `/fp:strict`.

Pixel layouts describe encoded storage, positive byte row/pixel strides, an encoded-coordinate crop, and TIFF/EXIF orientation 1–8. The boundary validates the entire encoded span, including the last pixel, without requiring padding after the last row. It does not apply crop/orientation or model resizing. Geometry values are immutable; public quads remain normalized upright TL/TR/BR/BL.

`Geometry.hpp` owns encoded/upright transforms, normalized/image coordinates, region mapping, photo inference crops, crop editing, render validation/sizing and clipped output polygons. Coordinates use image edges (`0..width`, `0..height`); the explicit pixel-center orientation matrix uses `width-1`/`height-1` for bitmap adapters. Centered square framing is a region transform, including fractional edges for odd dimensions, independent of tensor resizing. Android's CameraX viewport still owns the negotiated framing crop; bitmap allocation, gestures and OpenCV warp resources remain Android-owned. Model-output interpretation and its acceptance rules migrate in Task 06; crop selection preserves the existing prediction validity threshold without applying the editor's minimum area.

Adapters supply a `PixelLease` whose owner token keeps both storage and any platform lock alive. The token must cover the supplied span and prevent mutation/reallocation for the lease lifetime. Algorithms synchronously borrow `const PixelLease&` and must not retain its view or pixel addresses. Copies extend the lease; the final token destruction releases the platform resource. Thread-affine tokens stay on their platform serial owner. `OwnedPixels` publishes immutable storage and can release its own handle while a lease remains alive. No JNI, Nitro, Android, UIKit or OpenCV type enters the public headers.

Policy timing for later migrations: callers supply signed 64-bit monotonic nanoseconds from one documented clock domain per camera. For Android policy migration, use `SystemClock.uptimeMillis() * 1_000_000` (monotonic uptime excluding deep sleep), preserving current capture/focus deadline semantics. Sensor elapsed-realtime timestamps must be mapped explicitly before policy comparison; never compare clock domains directly. iOS adapters must establish their domain explicitly. The core reads no clock and owns no thread or timer. A waiting decision returns its absolute deadline in the same domain (as `CaptureDecision.Wait` does today). The adapter owns wakeups and cancels them by generation. Policies without deadlines need neither a timer nor a generic policy interface.

Android must provide the existing imported `OpenCV::opencv_java4` target. The core never discovers or bundles another Android OpenCV runtime, so FastCores continues to pin that runtime's workers. Standalone host builds use an explicitly selected OpenCV configuration; this is a separate process from Android.
