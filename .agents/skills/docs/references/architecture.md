# Architecture

Code is the source of truth for mechanics, constants and signatures. This reference records ownership, contracts and reasons that are easy to lose during changes.

Read [Algorithm notes](algorithm-notes.md) only for image processing, capture quality, focus, torch or adaptive-detection rationale and measurements. Read [Development](development.md) for commands, validation procedures and trace limitations.

## Ownership map

Native paths below are relative to `android/src/main/java/com/margelo/nitro/documentscanner/`; algorithms live in `processing/`.

| Concern                           | Owner / entry points                                                                                                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Public API and generated boundary | `src/*.nitro.ts` → `nitrogen/generated/`; `src/index.ts` and React wrappers expose the public API. Never edit generated code.                                                                                      |
| Headless session, pages and files | `HybridScanSession`, `ScanSessionState`, `ScanSessionRegistry`, `SessionResources`; `SessionPageProcessing` runs analysis/rendering.                                                                               |
| Scheduling and publication        | `ScannerWorkQueue`, `ScanSessionEvents`; `src/ScanSession.ts` owns immutable JS frame publications.                                                                                                                |
| Camera and live guidance          | `HybridDocumentScannerCameraView`; `LiveDocumentDetector`, `LiveQuadStabilizer`, flow/motion policies and `FocusPolicy`.                                                                                        |
| Inference                         | `DocCornerSession`, `QuadModelStore`, `NativeTensorPreprocessor`; canonical model under `resources/doccornernet/`, packaged as Android assets, verified by build hash and regenerated by `tools/models/`.          |
| Native image consumers            | `SessionPageBinding`, `ScannerImageReads`, `ImageLoader`; viewer/pager/thumbnail/crop Hybrid Views. `PageThumbnails` owns the shared thumbnail cache.                                                              |
| Export and sampling               | `SessionExportSnapshot`, `SessionExports`, `PdfWriter`; `SampleCollection` and `SampleFolders` own process-wide collection/folder state.                                                                           |
| Example app                       | `example/lib/scanSession.ts` holds the UI reducer; `useScanReview` combines React UI state with native metadata; `example/app/index.tsx` composes camera/review. `pdfExports.ts` owns host export names/retention. |

`HybridDocumentScannerProcessor` is a stateless session factory plus sample-folder controls. It owns no second image queue, model lifetime or disposal namespace. `CameraPermissions` owns process-wide permission independently of views.

## API boundary

- Native entry points return a result/`ScannerFailure` union; public JS adapters reject with `ScannerError` and a stable code. Generated exception transport loses custom Kotlin fields, so diagnostic causes remain in native logs and display text belongs to the app.
- React wrappers supply concrete native prop defaults: removed React props become null, which Nitro optional props reject. Stable callbacks invoke the latest committed handler; native state callbacks may replay when installed.
- Public image operations use session/page IDs, not image URIs. Metadata exposes no image paths, artifacts or render caches. Standalone native pixel-fixture helpers are test-only and reject session paths.
- JPEG quality is 0–1, converted once to Android percent. Internal -1 means omitted; zero is a valid public value, while CameraX's minimum explicit quality is 1.

## Session lifetime and resources

- A session is headless and explicitly closed. Camera/image view attachment and JS wrapper collection do not dispose it; the registry retains native state through physical cleanup. Views borrow the session.
- Native state owns page membership and order. Snapshot `pageIds` is ordered. The pager follows it when its optional `pageIds` prop is omitted; a changed complete prop order updates the session. `setPageOrder` supports headless/custom controls. Order changes publish an optional ordered-ID delta through the same subscription.
- The registry reserves `sessions/session-<opaque-id>` directories before creation, protecting them across JS contexts and Fast Refresh. Startup cleanup removes unregistered generated session directories and exact pre-session image filenames at the cache root; it preserves unrelated entries and never follows legacy-file links.
- Originals are immutable. Every render derives from the original, never another render. Original/frame/render/thumbnail resources use leases: retirement rejects new leases immediately; physical deletion waits for producer, decoder, view, sample and export pins. Transactional outputs remove partial/stale files.
- Session-owned analysis, rendering and image reads use the shared serial image FIFO. Reads hold independent pins after admission; queued cancellation releases them without decoding. Do not block that worker waiting for work queued behind it or for session cleanup.
- `close()` immediately rejects new commands/registrations and cancels queued session work. It settles after running work, producer/read pins, model release and already-claimed export publications drain, then removes files on the cleanup coordinator. Failed directory cleanup remains registered/logged for later process cleanup.

## Page processing and snapshots

- Source admission freezes normalized render defaults and model selection. The worker acquires the interpreter lease. Native state owns authoritative analysis, effective settings, requested/ready revisions and separate analysis/render failures.
- Awaited public mutations and captures publish accepted native state before resolving; background analysis/render completion remains observable through readiness metadata. Analysis precedes the first render. Explicit crop geometry wins over a later analysis candidate; filter/shadow edits retain useful analysis.
- Only the current revision publishes readiness/failure. Compatible stale results may populate per-filter/shadow cache slots; incompatible results retire through leases. Keep the previous displayed artifact until replacement, including after render failure. Equal settings are no-ops except retrying a failed render.
- `ScanSessionEvents` updates only affected page metadata under the state lock and emits changed/removed IDs, incrementing `sourceVersion` only for observable changes. Full immutable snapshots are cached lazily for registration and recovery. Registration and its initial snapshot are atomic. Delivery is FIFO on the Android main owner, outside the lock; unsubscribe releases callbacks. Close suppresses unclaimed old deliveries and sends terminal metadata once.
- `src/ScanSession.ts` owns transport reconciliation, not processing. It buffers registration callbacks, ignores old native versions and reconciles gaps with a full snapshot. A failed recovery retains consistent state and retries on the next change. Background events remain pending until one animation-frame publication; a successful command synchronizes a full snapshot and publishes before its Promise resolves. `getSession()` returns only the last published immutable value; unchanged pages, membership and whole snapshots retain identity.
- Stable `subscribe`/`getSession` support `useSyncExternalStore`. Subscribe has no eager callback; plain consumers use read → subscribe → read. Install snapshots before notifying; listener mutations/errors must not interrupt other listeners.
- JS `close()` calls native immediately and caches one cleanup Promise. Terminal publication releases the observer, scheduled frame and listeners. Cleanup rejection is logged even if ignored; callers still receive it. Missing terminal callbacks reconcile after cleanup, and failed initial registration closes the new native owner.

## Camera and capture

- CameraX follows permission, attachment and Activity visibility: background/detach unbinds, foreground rebinds. Disposal rejects pending view Promises. Permission is checked/requested independently; Activity resume refreshes status because Android has no permission-change callback. Concurrent requests share a keyed ActivityResultRegistry prompt; Activity destruction rejects waiters.
- Full-size 4:3 capture is preferred. A shared viewport crops analysis to the capture aspect; square capture previously discarded the frame edges. A `LifecycleCameraController` binds the use cases in one `SessionConfig`, with the frame rate, and shows them on the `PreviewView`, whose taps the scanner handles; it takes the viewport from the `PreviewView`'s size and scale type, so a square frame switches the preview to `FILL_CENTER`. It drops the session's Camera2 interop options when it rebinds, so the per-frame capture callback is set on the camera control, where options persist and update incrementally. Camera2 interop is used only where CameraX has no API: per-frame capture results, still-capture results and camera characteristics.
- Prop changes requiring rebind wait for an active capture. `mode='off'` stops camera analysis/use cases/gyro after an in-flight shot; `guide` controls guidance only. A torch change also waits for the shot, and capture waits for asynchronous torch confirmation.
- `takePhoto` requires a native-backed session. Native admission reserves one request before posting to main; overlapping calls reject `capture/busy` until physical work actually settles, even if its Promise already rejected.
- The camera holds render defaults in `Camera.renderOptions`; `takePhoto` only accepts capture-gate options. Saved pages are edited with explicit page-ID methods. Admission pins original/frame writers and freezes camera render options, model, gate overrides and applied camera settings. Readiness still uses live frame/focus/torch observations. CameraX saves the original without re-encoding; a keyed CAPTURE job describes the source and optionally writes an unfiltered placeholder frame. Successful source admission inserts the native page, starts processing and returns its ID.
- Session close/replacement or camera detach rejects the capture once and invalidates publication. Physical shots/source savers retain their slot and pins until settlement. Suppress stale stages/previews; observe close against the captured owner so an old close cannot cancel a replacement.
- `onCaptureStateChange` replays `unavailable/ready/waiting/shooting/saving`. Unavailable covers off, absent/closed session, startup, permission/attachment loss and obsolete in-flight owners. Exposure start (`captured`) means the user may move; saving can still fail afterward.
- The event-driven `CaptureGate` owns focus/readiness deadlines and takes one shot. It consumes complete frame records and treats missing motion as unknown; the camera view, not the gate, starts any capture scan. Flow judges motion blur with gyro fallback because OIS can cancel gyro motion. Read [capture-quality details](algorithm-notes.md#capture-quality) before changing these gates.
- User-facing capture/permission/start-error text belongs to React. `onCaptureStage(stage, waitReason?)` emits changed gate reasons while waiting, independently of captureFeedback; the reason is absent at other stages and before the first gate decision. Permission APIs and typed camera errors replace native status labels.
- Capture feedback is native over the frozen frame, retaining the shutter-time outline. Waiting pulses; shooting progresses until exposure. Successful capture shares one bounded shutter bitmap through its session. Attached image views seed from it immediately while decoding; a decoded thumbnail releases the session reference, and removal/close clears it. Displayed views keep their own bitmap references. No React readiness handoff is required.

## Live guidance and focus

- Live pixels remain native. Live detection guides but never captures; post-capture analysis is authoritative. Model score does not gate acceptance. Valid quads require finite normalized convex corners and minimum area.
- Accept valid model results immediately. Missing/invalid results retain an outline only when reliable flow carried it on the same frame. No agreement chain, averaging or reconstructed-corner fallback. Acceptance IDs remain monotonic across resets so expired results stay expired.
- One shared model loader validates/warms local `Camera.quadTensorModel` sources using float32 NHWC dimensions. Camera startup waits for preparation; source I/O is separate from inference, only the newest request activates, and model changes wait for captures. Errors reach `onError`; the host owns downloads/caching/hashes. No public preload or fallback model API.
- Continuous autofocus, aimed at the guide, runs whenever no scan holds the lens; captures count only focus reached after the page arrived. `FocusController` runs tap and capture scans; its generation snapshot restarts capture's stable sequence, and focus never pauses inference.
- Adaptive inference pauses while reliable homography flow carries a trusted outline. Tracking/feature loss or a corner straying more than 5% of the frame width from the confirmed outline wakes it; ordinary motion and focus do not. `AdaptiveDetectionPolicy` owns this pacing in Kotlin; the shared guide and flow supply its inputs. There is no periodic recheck, so texture-preserving changes can remain unseen until a wake condition. See [algorithm notes](algorithm-notes.md) for document focus, torch, thresholds and limitations.

## Native image views

- Viewer, pager, crop editor and thumbnail bind a session and page IDs. `SessionPageBinding` observes native state directly, independently of JS frame batching. Image sources prefer displayed render + thumbnail, then capture frame, then original; CropEditor always uses the original with an unsubmitted outline.
- `SessionPageBinding` alone classifies its target, identically on Android and iOS: a page it has seen (in its registration snapshot or a read) is removed or closed when absent, which clears pixels silently; a page it never saw is `input/invalid`. The same rule applies on registration, refresh, event delivery and restart, so an update queued past removal, removal racing the first read, and a detached view attaching after removal or session close all clear without an error. The binding also suppresses unchanged sources, so loaders load every source it delivers and keep only their publication-validity checks; retry stays an explicit loader operation.
- The shared thumbnail cache owns its memory policy at process scope, independent of any view: Android registers process memory callbacks, and iOS empties each cache when the app enters the background. Views only report their own visibility.
- Bindings and admitted reads have separate leases. Detach/removal/close invalidates publication immediately; cleanup waits for physical reads. Display sources survive replacement fades. Shared/published bitmaps stay with the render thread/GC; recycle only private results that were never published. Detach releases observers/pins; hidden/zoom-reset UI releases full decodes; reattach retries failed reads.
- Pager selection and callbacks use page IDs; indices remain internal. `auto` direction inherits the platform layout direction (Android view hierarchy; iOS app/trait direction). Reordering retains the selected ID unless an explicit selected page ID requests another. Session replacement clears old bindings; unknown configured IDs report `input/invalid`. Observed page removal or session close clears pixels without an error event; the host chooses the next selection.
- Each platform's pager recycles viewer cells (Android RecyclerView, iOS UICollectionView) and lays out one page beyond each side so neighbours have thumbnails before a swipe reveals them; cells leaving that window release their bindings and images. The pager is the single gesture arbiter: paging is disabled while the shown page is zoomed, so its drags pan, and enabled at the fit when `swipeEnabled`. Programmatic selection jumps without animation and without `onPageChange`; any page left fits again. Only the shown page reports load failures; a neighbour that failed retries once shown.
- Thumbnail tiles read only a displayed thumbnail or capture frame, otherwise render empty. They never decode originals/full images. Reads are bounded by tile size and use shared cached thumbnails; resizing retains same-page pixels until replacement. Rebinding clears immediately; unknown/closed pages remain empty without callbacks.
- `ImageZoom` and `CaptureFeedbackTimeline` keep their math free of Android types for JVM testing.

## Exports and samples

- Export admission freezes session order by default, or explicitly supplied IDs/order (including duplicates), requested settings/revisions, cache pins and original leases under one state lock. Unknown IDs/current render failures reject; an older displayed revision is never a substitute.
- An automatic crop retains invocation-time explicit geometry and its already-requested analysis outcome. Required analysis runs before export in the shared FIFO, even after page removal while an export needs it. Analysis failure rejects; no candidate means full frame. Missing artifacts render inline from pinned originals as private temporary results, without changing live page revisions/cache/display.
- Outputs must be outside reserved/registered session directories, including canonical aliases. Encode/copy to unique external staging files. Publication claims admission under the state lock, then validates, moves and rolls back outside it. Close rejects new claims and waits for claims already admitted; cancelled/failed exports clean staging, partial moves and pins. Successful external outputs survive close.
- `createPdf` uses react-native-images-to-pdf option meanings but its own writer. `cover` clips placement without removing hidden pixels. Eligible JPEGs/4-bit gray PNGs embed unchanged unless DPI/quality requires re-encoding; EXIF changes placement, not pixels. Pages stream one at a time through a temporary output.
- Sampling is human-triggered and process-owned. `SampleCollection` alone controls collection generations; stop/forget/revoked grants invalidate earlier recorders. Stop preserves the folder grant; forgetting releases it. Samples save raw model output from its own frame, not a tracked guide; retain original analysis resolution for later models.
- `saveCaptureSample(pageId)` pins the original and freezes the shutter guide, completed analysis and model provenance before queuing; it never substitutes a global model/cache. Storage saves the exact inference input losslessly with the model's prediction, unlabeled; never the original JPEG or a page outline, since user corrections must not enter training data. The folder is frozen at admission. Sample names use the shutter time while the photo is among the last few taken with collection on, else the save time.
- Samples are flat image/JSON pairs for `tools/label-samples`, with normalized upright quads, prediction, model hash and device. Picked folders use persisted SAF grants; no storage permission is needed. Detailed buffering/storage mechanics belong to `SampleCollection`/`SampleFolders`.

## Example app policy

- The outer scanner owns one native session and closes it on replacement/unmount without awaiting. New scan remounts the UI with that owner. Camera tuning and the shadow default are ordinary parent state, passed directly to Camera and Options rather than through the review hook. `useScanReview` exposes `ScanReview` UI state; `reviewCapture`, `submitCrop` and `cancelCrop` describe UI actions explicitly. `ActionButton` represents ordinary press actions. The scan UI has one native metadata subscription and a React reducer for selection, navigation and crop-screen visibility; there is no app external store or metadata copy. The owner ref is used only to close the current session. Awaited capture, commands, sampling and exports share an immediate UI busy lock and loading overlay; New scan, Back and conflicting controls remain blocked until completion. No session identity checks are passed through the UI.
- React owns selection, camera/summary/review navigation, crop-screen visibility, default shadow setting and an immediate operation UX lock. Captures only open review; native snapshots supply ordered pages; the app only reconciles selection and navigation. The app applies the 50-page policy and A4/200 dpi, Original filter and saved shadow defaults at capture.
- Keep one camera and one pager mounted. Review/crop/Options put the camera off and disable guidance. Native session placeholders cover the first image decode. Native images update independently of React tiles; the strip supports selection only, with no drag UI.
- CropEditor initializes its native draft from the saved quad when its page changes. No crop/Auto crop invoke native presets; `getQuad` is an optional draft read for custom controls. Cancel unmounts it. Presets replace the draft as actions, with no selected indicators or JS quad comparisons. Submit calls `editor.submit()` to validate and apply the draft directly to the native page; Cancel sends no mutation. Custom geometry remains available through `session.setDocumentCrop`. Filter/shadow edits persist immediately across Back. Edits remain available during processing; completion/export waits for readiness. Sample is disabled during analysis, whose input and prediction it saves. Zoom stays native; Crop is explicit so double-tap zoom never waits for a single-tap delay.
- Export/share/gallery holds the UX lock through success or failure. Use unique host-owned files/directories under the export cache, outside native sessions; recipients may read after sharing returns. Startup deletes only recognized host exports older than seven days. No JS image janitor.

## Crop observations, format policy and cancellation

- CropEditor classifies its draft natively and emits `onPresetChange(none | auto | custom)` initially and after presets/drags. Full frame takes precedence over an equal auto candidate. Consumers need no geometry copy to label a toggle; the example retains two fixed preset buttons.
- `format: auto` remains a render input across filter edits. The native renderer and destination allocator resolve it together: blackWhite uses 4-bit gray PNG; grayscale and other filters use JPEG. Explicit JPEG/PNG behavior is unchanged. Cache/export snapshots freeze the policy and filter; JPEG quality survives temporary switches to PNG.
- Superseded transport results become `ScannerCancellation` with the standard `AbortError` name at the JS boundary. They remain rejected operations, distinct from `ScannerError` failures, and preserve their reason code. UI operation boundaries ignore cancellation without comparing domain codes.

## Shared engine integration

Portable algorithms live in `cpp/include/document_scanner` and `cpp/src`; Android JNI adapters borrow leased pixels synchronously. Main's sessions retain admission, ordered page membership, revisions, file leases, source immutability, cancellation, and publication. Android retains decoding, codecs, CameraX/sensors and platform torch/capture gates.

Production `DocumentRenderer` keeps region-based upright JPEG decoding and transactional session destinations. It passes full-photo dimensions, decoded-region origin and sample factor to the shared warp/filter stage; submitted geometry is validated in full-photo coordinates before mapping to decoded pixels. Rendering and filtering compose within one native call; PNG can consume a synchronous native gray Mat lease. `PdfWriter` keeps file/codec resources and atomic publication while the shared core owns streaming PDF layout and serialization.

The active task index tracks shared-engine/iOS migration. The earlier native-session plan is preserved separately at `Tasks/native-sessions/TASKS.md`.


## iOS source and inference owners

`SourceStore.shared` owns immutable originals, a bounded full-source/thumbnail cache,
and counted pixel/file leases. `CornerInference.shared` owns model selection and
one serialized CPU interpreter/workspace, independently of views and sessions.
Callers freeze `Selection` at photo admission and retain a native inference lease.
A successful validated/warmed replacement advances its immutable generation;
failed or stale replacement preserves the selected model. Historical photo work
may switch the runtime without reactivating that selection for live guidance.
Live consumers must check their selection generation before publishing guidance.

Photo workers acquire source pixels before entering inference; the inference queue
never calls back into source storage. Shared crop geometry selects the seeded
region and maps the one fresh prediction into normalized full upright coordinates.
iOS reads the full leased region directly; Android retains its half-resolution
platform decode. Both use the same shared tensor resize/normalization/decoder.
JPEG reload can change pixels; parity is measured within the declared photo budgets.

Live packed RGBA/BGRA buffers are retained and locked only inside synchronous
inference, with crop/orientation applied by the shared preprocessor. All exits
unlock on the same worker. Lease close rejects new calls immediately and queues
release behind in-flight work; the last owner releases runtime/workspace on that
worker. Frozen selections retain model bytes for later photo work. These services
are internal prerequisites; later tasks wire public sessions and camera guidance.
