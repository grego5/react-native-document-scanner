# Architecture

Code holds the mechanics and constants. This file records ownership, invariants, and the reasons and evidence behind them.

## Ownership

Native code lives under `android/src/main/java/com/margelo/nitro/documentscanner/`, with `processing/` below it.

- `src/*.nitro.ts`: native contracts; `nitrogen/generated/` is generated from them. `src/index.ts`, the React wrappers (`DocumentScannerCamera.tsx`, `DocumentCropEditor.tsx`, `ImageViewer.tsx`) and `CameraPermission.ts` are the public API. `ScannerFailure.ts` / `ScannerError.ts` and `ScannerErrors.kt` carry failures.
- `CameraPermissions.kt`: process-wide CAMERA permission; `HybridCameraPermission.kt` exposes it.
- `HybridDocumentScannerCameraView.kt`: CameraX binding, capture Promises and gates, focus, overlay and hints.
- `processing/LiveDocumentDetector.kt`: live analysis on its own executor: inference, flow, pacing.
- `processing/LiveQuadStabilizer.kt`: which candidates the guide shows. `LiveQuadMotion.kt`: gyro homography and rectangle/tilt geometry.
- `processing/FlowMotionEstimator.kt`, `FlowQuadMotion.kt`: optical flow and fitted page transforms. `MotionBlur.kt`: gyro and flow blur.
- `processing/AdaptiveDetectionPolicy.kt`: when tracking replaces inference. `DocumentFocusPolicy.kt`: document-driven focus.
- `processing/DocCornerSession.kt` and `android/src/main/cpp/NativeTensorPreprocessor.*`: LiteRT model and tensor conversion. `processing/SampleCollection.kt`: sample collection's state, kept frames and writing; `SampleFolders.kt`: the private file directory or picked SAF tree, its grant and stored settings. The model is in `android/src/main/assets/doccornernet/`; the build verifies its SHA-256 and `tools/models/` regenerates it.
- `HybridDocumentScannerProcessor.kt`: `analyzePhoto` and `renderDocument` on a bounded serial executor, cache removal on another. `processing/DocumentRenderer.kt`, `ShadowRemoval.kt`, `DocumentFilters.kt`, `InkDetail.kt`, `GrayscalePng.kt`, `PdfWriter.kt`, `CachedImageFiles.kt`: rendering, shadow removal, filters and their ink evening, 4-bit PNG, PDF and scoped deletion.
- `CropEditorView.kt`, `CropQuadEditing.kt`, `HybridDocumentCropEditorView.kt`: the crop editor.
- `CaptureFeedbackView.kt`, `CaptureFeedbackTimeline.kt`: capture progress drawn over the preview; the timeline has no Android types, so JVM tests cover it.
- `ImageViewerView.kt`, `ImageZoom.kt`, `HybridImageViewerView.kt`: the zoom image view (`ImageViewer`). `ImageZoom` holds the fit, pinch, pan clamp and double-tap math without Android types, so JVM tests cover it.
- `ImageLoader.kt`: loads one viewer's page while its view is attached: the thumbnail first, the full image only while zoomed. `PageThumbnails.kt` is the process-wide thumbnail cache by page uri that renders and captures fill, and its memory callback.
- `ImagePagerView.kt`, `HybridImagePagerView.kt`: native paging between viewer pages (`ImagePager`), a `RecyclerView` that blocks paging while the shown page is zoomed.
- `processing/LatestFrameCapture.kt`: writes the latest live analysis frame at the shutter as the capture's `frameUri`, the page straightened, and caches it as that page's thumbnail.
- `android/src/testSupport/java/`: Kotlin preprocessing oracle and trace format, tests only.
- `example/app/index.tsx`: the only screen. `example/lib/scanSession.ts`: pure session reducer, driven by `example/hooks/useScanSession.ts`. `example/lib/cachedImageJanitor.ts`, `pdfExports.ts`: file cleanup.

## Invariants and reasons

### API boundary

- The wrappers pass every native prop a concrete value: React sends null for a removed prop, and Nitro optional props reject null.
- Native callbacks re-send the current state when set, so the wrappers pass stable functions that call the latest handler.
- The generated bridge keeps exception text but not custom Kotlin fields. Native entry points therefore resolve a union of the result and `ScannerFailure`, and the JS adapters reject with `ScannerError` and a stable `code`. Diagnostic causes stay in native logs; display text belongs to the app.
- JPEG quality is 0–1 everywhere, converted once to Android's percentage. Internally -1 means omitted, because 0 is a valid public value and CameraX's minimum explicit quality is 1.

### Camera binding

- Capture sizes rank full-size 4:3 first. The shared viewport crops analysis to the capture's aspect, and an earlier square capture cut analysis to the frame's centre.
- `Camera2CameraControl.setCaptureRequestOptions` replaces all options, so a new option must be merged into the same request.
- A rebind during `takePhoto` fails the photo, so prop changes that rebind wait for captures to settle.
- `mode='off'` stops use cases, analysis and the gyroscope; a capture in flight finishes its shot first. `guide` only controls guidance.

### Images

- The captured JPEG is never modified. Renders and filters always derive from the original, never from an earlier output.
- Detection decodes at most 2000 px: all 13 reference photos keep identical predictions, while 1800 px fails sample 08. Rendering decodes separately, up to 4096 px.
- Live detection runs one full-image inference; photo analysis runs one inference on its selected region. Live results are accepted immediately; adaptive inference can pause on the next reliably tracked frame. There is no pending live crop or second inference. Photo analysis decodes the saved photo (up to 2000 px) and runs one fresh inference. An optional live quad selects its bounding region with 10% margin per side, expanded to the photo aspect ratio and shifted within image bounds; predictions map back to the full upright photo. Without a valid seed it uses the full photo. The guide still seeds the initial crop preview. Both selected inputs use the existing square tensor resize; analysis requests 640x480 and the bundled model input is 224x224.
- Filters even the lighting with one paper-brightness estimate that divides every channel: per-channel division turned a broad pastel patch white. `blackWhite` is a continuous curve, not a threshold, because thresholding discarded faint strokes. Filter constants are starting points, not tuned on a range of real pages.
- After evening, `InkDetail` deepens faded thin ink and sharpens soft areas per tile (8 across the short side), since glare and distance from the lens leave parts of a page with weaker ink and softer edges. Ink depth is a black-hat about a text line wide, kept per pixel, and only that depth is deepened, so a gray box sharing a tile with faded text keeps its tone. Text-free tiles borrow their neighbours' values; sharpness is relative to the tile's depth, so it reflects blur alone. Both fold into the unsharp mask x + a × (x − blur) − (s − 1) × ink.
- Passes that apply a small map per pixel run natively (`FieldKernels`): the ink pass, shadow removal's gain, and the divide by the paper, which also applies the white balance (in the gray weights for the gray filters). Each map is enlarged a row at a time as `Imgproc.resize` with INTER_LINEAR would; rows run in parallel, 16 pixels at a time, in the float order of the OpenCV passes they replaced and without fused multiply-add, so output matches within one level. On the SM-G998U, for a 4096x3072 page, the ink pass fell from about 77 to 16 ms and the gain from 65 to 9 ms; `enhance` takes about 210-230 ms, `grayscale` and `blackWhite` 160-190 ms, shadow removal 35-130 ms. `RenderTimingTest` (`-e measure true`) times the stages.
- Renders and filter previews run in `FastCores.run`, which pins the calling thread and OpenCV's workers, by thread id, to the cores the kernel's `cpu_capacity` rates at least half the fastest (or at 70% of the top clock where none is exposed), and releases them after the last overlapping call, since the workers serve the camera too. After an idle pause, as between captures, the scheduler left much of a render on slow cores: on the SM-G998U its median fell from about 340 to 255 ms on the four big cores, faster than the mid or prime cores alone. It pins anew on every call, as backgrounding resets affinity, and does nothing where no core is markedly slower. Performance hint sessions are unavailable there, and the public API has no hint for a one-off burst.
- Corner inference, live and photo, runs on one interpreter thread that pins itself to the prime cores, those rated as the fastest, before every task (`FastCores.prime`), with one TFLite thread. On the SM-G998U a warm inference takes 9.4 ms on any thread count, rising to about 33 ms after 300 ms idle as clocks drop; in live preview, inference with frame preparation took a median 24 ms pinned against 29 ms left to the scheduler, which spread it over the big cores, and 24 against 32 ms after a pause. Optical flow stays unpinned on the analysis thread.
- Monochrome PNG output is 4-bit gray, so gray text edges survive. There is no 1-bit output.

- Bent edges (`followPageEdges`, on by default; `PageEdges`): on an 800 px rectified copy with a 6% band, 31 stations per side take the strongest colour step, and t(1 - t)(a + bt + ct²), pinned at the corners, is fitted by a search over station triples then least squares (a + bt alone missed printer pages near their corners). A side bends only when at least 16 stations agree within 1.5 px, the agreeing stations reach both corners (so a printed rule mid-side cannot pair with the paper edge), the bend lies between 1.5 px (smaller ones were wavy flat edges) and the band, and the edge stays in the photo. Sides join by a Coons patch before the inverse homography. `validContentPolygon` comes from the straight warp, so bending is skipped when a corner lies outside the photo. The map is built natively (`PageEdgesRemap`, -O2 in debug too) a 128-row strip at a time and resampled with `remap`: on the SM-G998U edges take 25-38 ms and the curved warp 31 ms against 18 ms straight, where building the map in Kotlin or with OpenCV calls took 110-125 ms.

- Shadow removal (`removeShadows`, on by default) runs on the warped page before the filter, so the filter's own paper estimate sees even light; run after it, the shadow had already been flattened and toned. It replaced an SCI low-light model with soft and hard modes: SCI's 258-weight estimate read dense text and printed photos as shade, Soft left moderately shaded areas half corrected, and its colour matching was a second heuristic on top. The estimate now closes ink away (a square 2.5% of the reduced short side) on the brightest channel of a copy at most 512 px long, since ink keeps one bright channel and shade darkens all three, then lifts toward the 90th percentile, capped at 2x. On a page with a hard sun shadow, the filters without it left a blue patch (`enhance`) or a grey half (`grayscale`, `blackWhite`); with it first, all three came out evenly white. A guided enlargement of the gain looked the same there, so the gain is enlarged bilinearly. Areas wider than the closing kernel and darker than paper, such as fingers, are lifted too.

### PDF export

- `createPdf` takes `react-native-images-to-pdf` options with the same meanings, but it is its own writer: `cover` clips at the page instead of cropping pixels, so the hidden part stays in the file.
- 4-bit grayscale PNGs and eligible JPEGs are embedded without re-encoding unless `targetDpi` shrinks them (or, for JPEG, `jpegQuality` is set). EXIF orientation goes into the placement matrix, never into pixels.
- Pages stream one image at a time into a temporary file that then replaces the output.
- The example shares a new file per export, because a recipient can keep reading after the share sheet returns. Startup deletes its own exports older than seven days.

### Capture quality

- Optical flow judges blur; the gyroscope is the fallback. In recorded A4 scenes the gyro flagged sharp OIS-stabilized frames as blurred, while flow ignores rotation that OIS cancels and also sees translation and approach. Twelve captures split at 0.2%: steady ones had at most 0.09% flow blur, moving ones at least 0.31%.
- There is no age limit on frame results: the newest one is the latest knowledge there is, and a fixed limit only rejected good results from slow inference. Analysis writes a record for every frame it receives, so records go old only when analysis stalls, such as while the model loads. A capture approved, after a focus or torch change, on a record an earlier evaluation already read logs its age. Missing flow is unknown, never steady.
- Flow speed is the fastest page region, so one waving region decides.
- Zero shutter lag only saves a frame from CameraX's buffer if that frame reported AF focused (locked or passive), AE converged and AWB converged; otherwise CameraX quietly takes a new picture. Photographing a 240 Hz counter showed both: with the page already locked the photo was a buffered frame about 60 ms before the shutter, while a capture that had just waited for focus saved a new frame about 340 ms after it, which caught a shake the motion check had passed. Supported autofocus ZSL captures therefore wait until the newest judged frame reports those three states.
- Capture checks complete frame analysis results rather than separately updated values. The analyzer records one `FrameRecord` per analyzed frame: that frame's own capture result (AF, AE and AWB states, exposure), its flow from the previous analyzed frame, its motion blur and source (flow over its exposure, else the gyroscope), calculated once and shared with analysis and traces, the gyroscope's speed over the flow interval, and the confirmed in-frame guide after it. Capture reads them in order from a bounded `FrameHistory`, each once, so a busy main thread delays evaluation without losing frame results; a reader more than 32 frames behind is told so and restarts its sequence. Only frames exposed after the latest focus change count. A frame whose capture result had not arrived when analysis started is looked up again when it is recorded; one still without it keeps the sequence through it, checking speed and the page, but does not count. While focus is required, a frame that reports focus lost restarts the sequence.
- Three checks decide whether a frame continues the stable frame sequence, since they answer different questions: framing (flow under 5% of the frame width per second, whatever the exposure, with gyroscope speed where texture is too sparse for flow), motion blur (the frame's own blur within `captureBlurPercent`), and in `scanner` mode the page's drift from the sequence's first frame (position 2%, scale 3%, shape 2% of corner travel). Four consecutive analyzed frames must pass, and the sequence must reach the newest frame. Missing, broken or non-consecutive flow, unknown motion blur or a missing page restart it. The thresholds are starting settings from the recorded split below 0.09% and above 0.31% blur at a typical 30 ms exposure.
- One `CaptureGate` per capture owns readiness and both deadlines and returns wait (with its reason), shoot or reject; hints come from the reason. Its input is `CaptureState`, with separate ZSL and torch readiness. The gate applies the ZSL bypass in the same evaluation that skips optional focus; torch readiness remains required. Focus, with its page in `scanner` mode, waits up to `focusTimeout`; once it holds, everything must align within 1.5 s, and losing focus later waits within that same deadline. Without `requireFocus` either deadline bypasses the focus requirement but never light or steadiness. A lost page or lock reports `capture/focus-timeout`, exposure, white balance or a torch change `capture/failed`, motion `capture/motion-timeout`. The gate is evaluated on events (new frames, a focus or torch change, its deadline), never on a polling timer, and the first evaluation where all conditions pass starts capture, with no settling delay. Hardware-dependent choices, such as whether zero shutter lag applies, read the configuration the camera was bound with, not props changed since. CameraX still picks the buffered frame, so the photo approximates the approved frame sequence; the lifecycle log records each still's sensor time against the shutter. A capture takes one shot.
- A gated capture never starts a scan. In `scanner` mode with the guide it waits for a confirmed page and a document or tap scan's lock (see Document focus); otherwise for focused or locked state. Either waits up to `focusTimeout`, then rejects unless `requireFocus` is false. Passive autofocus has reported focus on a page far out of focus; a document scan's lock avoids that. The Samsung drops a trigger that arrives during a passive scan and never reports a lock for it, hence one retrigger after 700 ms. Fixed-focus cameras still require a confirmed page in scanner mode, but need no focus lock. Fixed focus is detected from AF modes, because Android may omit the minimum focus distance.

### Capture feedback

- `retainCapturePreview` keeps a successful shot's frozen preview until the caller sets it false, including while mode is off. Failure and disposal clear it. The example retains it through JPEG saving and review decoding, hiding the review panel until `ImageViewer.onLoad` installs its first image. ImageViewer keeps its previous image while replacements decode. Crop, filters and completion actions wait for analysis/rendering to finish; Retake remains available once review is shown.

- It is drawn natively over the frozen frame, so stage changes need no JS round trip, and from the shutter on it keeps the outline drawn at that moment, which is the one the frozen frame shows.
- Waiting has no known length (focus and readiness can take up to their timeouts), so it pulses rather than showing progress. A waiting capture takes priority over guide hints with find-the-page, focusing, lighting or hold-steady text while `captureFeedback` is enabled. Shooting has a short known length, so its line approaches 90% and closes only when the shot has been exposed.
- `captured` means the user may move: the shot has started exposing (`onCaptureStarted`), or the photo resolved. Saving continues after it, so a failed save can still report `failed`. The timings are starting settings.

### Torch

- Auto decides from the exposure time and ISO that auto-exposure already reports for every frame, so it needs no pixel work. Their product grows as light falls; the dark threshold and one-second wait are starting settings, and the stats strip shows the live product for calibration.
- Once lit, auto stays lit until the camera stops or the mode changes. A lit torch brightens the page, so exposure no longer shows the room's own light, and switching off to look would flicker.
- Auto does not use Camera2's flash-required AE state: that needs auto-flash AE mode, which also fires the flash for stills and disables zero shutter lag.
- A torch change waits while a photo is in flight, so the light cannot change during its shot. CameraX confirms a change asynchronously, so a photo also waits for one sent just before the press.

### Live guidance

- Live pixels stay native. Live detection is guidance only and never captures; post-capture analysis is authoritative. The model score never gates acceptance.
- The guide accepts each valid model result immediately, with no agreement chain, averaging or reconstructed corners. Missing or invalid results keep the old outline only when reliable flow retained it on that same frame; otherwise it clears. Flow carries the outline while inference is paused.
- Acceptance ids keep rising across stabilizer resets, because the main thread drops ids it already expired.
- Camera configuration stays on React props; the view owns callbacks, capture presentation and activity. Sample destination and collection controls stay on `DocumentScanner`.
- `Camera.quadTensorModel` requires a local path or URI. A shared Kotlin loader validates and warms the model, inferring dimensions from its float32 NHWC input. The camera stays off until ready and reports failures through `onError`; there is no fallback or public preload API. Matching requests reuse preparation, source changes wait for captures, and stale callbacks are ignored. Source I/O runs separately from inference; only the newest request activates. Sample predictions retain their model selection. The host owns downloads, caching, progress and hashes.
- Binding or enabling the guide loads the model and runs one blank inference on the analysis executor, so camera start-up overlaps interpreter setup instead of the first frame paying for it. A failed preload is left to the first frame, which loads again and reports the failure.
- Live validity requires finite, normalized convex corners and minimum frame area. Rectangle reconstruction and inferred tilt diagnostics are removed.
- Inference uses framing speed as its motion gate; exposure smear and autofocus state affect capture readiness, not detection. Capture still checks its own ordered steady sequence and exposure smear. Boundary contrast sampling is not part of detection or adaptive pacing.

### Document focus

- Always on with `guide`. Detection and confirmation run independently of autofocus metadata; focus controls capture readiness and never blocks inference.
- A successful AF-only scan without auto-cancel holds focus. It refocuses on a confirmed size change or sustained sharpness loss, and releases after one second without a target. Tracked outlines count, so the lock follows the page while inference is paused. Taps keep five seconds of priority. A capture waiting for focus does not pause this: the policy keeps acquiring, refocusing and parking, and only a shot in flight holds the lens. One `FocusController` owns scans, tap priority, retries, timeouts, locks and parking, and publishes a snapshot whose generation changes on every start, settle and release; capture restarts its sequence on a new generation instead of focus code resetting capture state, and analysis trusts frames without metadata only while that snapshot holds a lock.
- While document focus is on, the legacy raw centre AF region is omitted so it cannot override CameraX's mapped target.
- `scanner` mode parks the lens between owned scans: autofocus off and a set focus distance, through the same Camera2 options, which are lifted for every scan. Continuous autofocus hunts on an empty scene, its lens breathing moves corners between frames, and it can settle on the background; a parked lens does none of that. It needs AF off, the manual-sensor capability and a minimum focus distance; other cameras keep continuous autofocus. So do captures that do not wait for focus (`qualityGate` off or a zero `focusTimeout`), which would otherwise shoot the parked lens unfocused.
- A parked lens is sharp enough to detect a page. In a simulated defocus sweep (36 SmartDoc frames with ground truth, 13 private photos), disk blur up to 1% of the long side never moved a detection to a different place; at 1.5% the first did, and at 2% several. A lens parked at 30 cm is estimated to blur pages from 15 cm to infinity by at most about 0.7% (6 mm f/1.8 lens, 9.6 mm sensor). Parked frames therefore confirm the guide, and the first scan waits for a confirmed guide rather than a provisional result.
- The parked distance starts at 30 cm and becomes each lock's reported distance, a tap's too, for the process, so remounts park where the user last focused. Uncalibrated lenses report their own monotonic units, which only learned distances match.
- Autofocus scans and lens parking do not pause inference or reset confirmation. Reliable optical flow carries the guide independently of inference throttling.
- A photo needs more focus than detection: about ±1 cm at 30 cm for a 4000 px photo. `takePhoto` therefore waits for the document scan's lock instead of shooting the parked lens. It starts no scan of its own: an earlier version scanned at the guide or the preview's centre from the shutter, and that focused on whatever the centre held when no page was confirmed.

### Adaptive detection

- Once a trusted model result locks the outline, flow carries it and inference pauses. The aim is to stay paused through normal handling, so movement alone never wakes inference: an earlier speed limit, then a net-displacement limit, both woke it on ordinary hand tremor.
- Tracking fits a homography, because a page is flat and tilt is then modelled exactly. Tilt bends far tracks away from any similarity, so a loose similarity consensus seeds the homography, which is held to the strict tolerance.
- Inference wakes when:
  - tracking is lost. The estimator always replaces its reference frame, so one failed frame breaks the chain.
  - a page region loses its features. Features are reselected every frame, so a covered region soon reads clean again; flow cannot show recovery, so any loss requests a model confirmation. Tracking time is kept, so a confirmation returns straight to the pause. Loss lasting 250 ms resets the policy.
  - the outline's shape changes beyond position, rotation and scale, because tracking error grows with tilt.
- Focus does not wake it: focus decides whether a model result can be trusted, not whether flow holds.
- There is no periodic recheck while paused, so a change that preserves the tracked texture goes unnoticed until a wake condition.
- The thresholds are starting settings.

### Sample collection

- Samples are human-triggered: a person who saw a bad outline saves it, so the saved set is mostly failures, not a stream of easy frames. Nothing is written until a save.
- Sampling is on only while a folder is picked and collection is not stopped; stopping keeps the folder and its grant, forgetting the folder releases them. Then the live detector keeps a copy of its latest inference frame, whatever the model found (a missed page is a sample too); each photo keeps its last frame before the shutter for the last 8 photos. That costs one 640x480 RGBA copy (1.2 MB) per inference and about 10 MB at most. Stopping collection drops them all at once.
- `SampleCollection` alone decides whether collection is on, and every change goes through one transition; a stop, forgetting the folder and a grant found revoked (on reading the folder, or on a failed write) all turn it off the same way. Each off bumps a generation: a recorder copying a frame and a photo between shutter and save carry the generation they started in, and are dropped if it changed.
- A sample records only the model's raw output on its own frame, never the guide after stabilizing or optical flow, which moves the outline between inferences: a label pairs the model's exact input with what the model said about it.
- Files go flat into the picked folder as `<ms>-<long edge>.png|jpg` beside `<ms>-<long edge>.json`; a photo and its frame share the shutter's `<ms>`. Each JSON is one `tools/label-samples` entry (version 2, quads normalized to the upright image) plus the prediction, the hash of the model that made it (not the one current at the save) and device, so the folder opens there without an import step and labels land beside their images. A photo's label is the outline the user accepted; a live frame's model outline is only a starting point.
- Frames are saved at analysis resolution, not model input size, so they stay usable when the model's input size changes.
- All storage work runs in order on one thread, since a picked tree can belong to a slow or remote provider. A photo is opened before its save is queued, so deleting it meanwhile cannot cut the copy short; saving it again replaces its files only in the same folder. A picked folder is a Storage Access Framework tree with a persisted grant, kept in the library's preferences; picking another releases the old grant, and a grant revoked in settings counts as none. No storage permission is needed.

### Example app

- The camera stays mounted for the whole session and uses `mode=off` with guidance disabled while the pager preview overlay, the separate crop screen, or Options is shown. New captures and saved pages share one `ImagePager`; saving replaces the draft entry without changing preview components. The overlay and pager remain mounted when hidden or covered by crop; opacity, touch handling and accessibility visibility hide them without removing their layout. A small thumbnail strip selects pages. Shadow and Crop are per-page toggles, filters use a modal, and Options owns the default shadow setting for new captures.
- Review has two modes, both session state on the draft: preview (default) shows the latest render in `ImagePager`; the separate crop screen (`cropQuad` set), opened by Adjust crop, shows `CropEditor` over the original and moves a separate outline, so the draft's quad and render change only on Submit. A crop or filter change outside crop mode renders from the original; a render the user has moved past is deleted, not shown. A preview counts only while it matches the draft's quad and filter, and accepting saves that render instead of rendering again. Opening a page reuses its saved output as the preview.
- Preview zoom is a native view rather than JS gestures: the example links no Gesture Handler or Reanimated, Android `ScrollView` cannot zoom, and native gestures avoid a JS round trip per touch. Crop mode is a button, not a tap on the image, so a double tap never waits on a single-tap delay.
- The janitor deletes owned files once nothing references them, waits for any analysis, render or export, and clears earlier launches' leftovers before the shutter enables.

## Lifecycle

Permission belongs to `CameraPermissions`, not the view, so an app can check and request it before any camera mounts. Android has no permission-change callback, so the status is re-read whenever an Activity resumes, covering both the prompt closing and a return from system settings. Concurrent requests share the open prompt, which uses a keyed `ActivityResultRegistry` registration so it works at any lifecycle point; destroying the prompting Activity rejects the waiting requests. An attached camera view binds on a grant.

Use cases follow permission, view attachment and Activity visibility: background or detach unbinds, foreground rebinds. View disposal rejects pending Promises. Processor disposal rejects tracked Promises and releases the model after in-flight work.
