# Host integration

Install `react-native-document-scanner` and `react-native-nitro-modules` and rebuild the app. The package declares React Native 0.78+ and defaults to Android API 24+. Expo uses a development build. On iOS follow the [host setup](ios/setup.md).

- Create a session with `DocumentScanner.createSession()` in a host lifetime boundary such as a React effect. Close it on replacement or unmount. Pass the same session to `Camera`, `ImagePager`, `PageThumbnail` and `CropEditor`. Use `useCameraPermission()` for permission UI.
- `Camera` resolves `mode="document"` or `mode="photo"` into explicit props for the same native view. Photo mode disables live document guidance and automatic correction. `active` controls camera use independently of session lifetime. The example starts a new session on mode changes as host policy.
- Capture via the camera ref. `takePhoto()` returns an admitted page ID. Observe `session.subscribe` and `session.getSession` with `useSyncExternalStore` for ordered pages and background readiness. Keep navigation and selected page in React.
- `session.importFromLibrary(options)` presents the system photo picker and imports the picks in the order they were tapped. It needs no library permission and no host picker package. Options are validated before the picker opens. It resolves with the admitted page IDs in picked order. Unreadable picks are skipped, and cancelling or a selection with no readable image resolves `[]`. Failing to write an original rejects with `storage/write-failed`; pages already admitted stay in the session. `maxCount` limits the selection. Android's document-picker fallback ignores the limit and keeps its own order, so the library imports only the first `maxCount` picks. One picker is open at a time, and another call rejects with `capture/busy`. If the Android Activity that presented the picker is destroyed first, the call rejects as a cancellation (`AbortError`). Closing the session settles a pending call with `processor/disposed` and completes once its picker has freed the slot; a call whose picker has not opened yet never opens it. Android cannot close the system picker, so it stays on screen and its result is dropped; iOS dismisses it.
- For files the host already has, use `session.importImage(uri, options)` or `importImages(uris, options)`. Android accepts `file://` and `content://`, iOS `file://`. Each image succeeds or fails on its own: an unreadable or undecodable image fails with `image/load-failed`, writing its original with `storage/write-failed`.
- Pass the camera's `imageCorrection`, `outputOptions` and `autoCrop` so imported pages match captures. An import resolves once its original is admitted and follows the app-wide model as it stands; a page admitted while the model loads shows its full image until analysis catches up ([architecture](architecture.md#ownership-and-publication)). Without a model the page keeps the full image for the crop editor.
- Camera `onError` can report the non-blocking `camera/analysis-slow` warning. It fires once per slowdown when a measurement window of at least three seconds averages below 15 delivered analysis frames per second. A healthy window or new camera run rearms it. Model inference pacing is measured separately.
- `imageCorrection` and `outputOptions` configure future pages. Output dimensions are in centimeters and JPEG quality is 0–1. Change an admitted page with session commands or submit its native crop draft. Export with `session.createPdf()` or `session.exportImages()` to host-owned destinations.
- See `src/index.ts` for public exports, the `*.nitro.ts` files for native signatures, and `example/` for a working host. [Architecture](architecture.md) owns the lifecycle and publication rules.

## Corner detection model

The package ships no model; the host passes one through `cornerDetectionModel`. Native validation requires one float32 NHWC `[1, H, W, 3]` input and one float32 `[1, 9]` output; the model's own H×W is used. Input is RGB normalized with ImageNet mean `0.485, 0.456, 0.406` and deviation `0.229, 0.224, 0.225`. Output is TL/TR/BR/BL corners normalized to the model input, then a 0–1 score compared with `minCornerScore`; corners outside 0–1 or not a clockwise convex quad find no page.

- Sources: `asset:///<path>` (Android app asset or iOS app bundle path), absolute paths and `file://` on both platforms; Android also `content://`, `android.resource://` and raw resource names, iOS also main bundle resource names.
- `Camera` passes the app's `mode` through and never switches by itself; the native view only enforces the profile. With `guideLiveCorners` or `autoCrop` on, the camera stays off until its model is ready, and `onDocumentStateChange` reports `loading`, then the live states, or `unavailable` with the failure on `onError`. The app lets the user wait or render `mode="photo"`, which needs no model and starts at once; photo pages keep the full image, and an active model only supplies the crop editor's detected outline.
- Failures: a source the platform rejects, or no model at all, reports `input/invalid`; a supplied model that fails to load or validate reports `model/load-failed`. Both reach `Camera` `onError` or `waitForCornerDetectionModel()`, never an import or an admitted page. A mounted camera keeps a failure until its source changes; a newly mounted `Camera` or another request for a failed explicit source loads it again, while a failed plugin model stays failed until the app restarts.
- Expo: the plugin option `{ cornerDetectionModel: '<path>.tflite' }`, relative to the app root, copies the file at prebuild into both apps as `corner-detection-model.tflite`. Prebuild fails if the file is missing. `Camera` and sessions default to that model when the app contains it. Removing the option leaves the copied file in place; run `expo prebuild --clean` afterwards.
- One app-wide model is active at a time. The first `createSession()` starts loading the plugin model, so headless hosts that only import get it without mounting a `Camera`. A `Camera` without the prop joins that load and follows any explicit source that replaces it. An explicit `cornerDetectionModel` replaces any other source, and the plugin model never replaces an explicit one, including a failed one, until the app restarts.
- `DocumentScanner.waitForCornerDetectionModel()` waits for the current load, starting the plugin model if nothing was requested yet. It resolves `true` once the model is active and `false` without any model. It rejects with `model/load-failed` or `input/invalid`, or with a `model/superseded` cancellation when a newer source replaces the load.

## Example app

The example's plugin option defaults to the upstream export in `example/assets/doccornernet/`; the example passes no `cornerDetectionModel`. `DOCUMENT_SCANNER_CORNER_MODEL` in git-ignored `example/.env` substitutes a local model, relative to `example/`; re-run prebuild after changing it. Wire the shutter to the camera ref and enable it when `onCaptureStateChange` reports `ready`. Its Gallery button calls `importFromLibrary` with the camera's current defaults, then opens review for one admitted page or the summary for several.
